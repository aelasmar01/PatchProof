## Limitations and residual risks

- **Scope of the results:** one Docker Desktop installation, on one date. They are not a
  guarantee against container-runtime vulnerabilities (§4.1). Re-verify after Docker
  Desktop upgrades and at each release gate.
- **User namespace:** shared with the Docker VM; Docker Desktop does not remap it. This is
  mitigated by the fixed non-root UID and zero capabilities.
- **Configuration-only claims:** four controls rest on configuration or kernel-reported
  evidence (see E2).
- **Statistical probes:** CPU enforcement is statistical. Log retention is measured
  through `docker logs`.
- **C4 exit code:** the shell exit code was not captured. The suite status and records
  establish the outcome.
- **Advisories:** `doctor` does not query advisories online; the Docker Desktop security
  floor reflects the 2026-10-11 review.
- **Hashes:** they support local consistency only, not independent attestation (ADR-007).
- **Git:** 2.42.0 is behind the reviewed 2.56.0 and must be resolved before PP-005.
  `~/.git` remains, pending an owner decision.
